# Stack

Every technology the site uses or plans to use: its pin, what it owns, why it won, and what came second. Also what was rejected, when upgrades happen, and what is new to learn. The two choices that shape the rest have their own records: [ADR 0002](adr/0002-host-on-workers-static-assets.md) (hosting) and [ADR 0003](adr/0003-astro-static-first.md) (framework). Toolchain mechanics (lockfile, catalog, Dependabot config) are in [delivery.md](delivery.md), and prices are in [cost.md](cost.md).

Status: Draft for review in PR 1 · 2026-10-22

## Shape

Astro builds static HTML in Node at build time. An assets-only Cloudflare Worker serves it, so a page view runs no code and costs nothing. Content pages ship a few small vanilla scripts and no framework runtime; React loads only on lab pages. The lab (Phase 4) is a second Worker that holds every Durable Object (DO) class. GitHub Actions builds, gates and deploys. Each layer is a Cloudflare product (on the Free plan; only the domain itself costs money), a pinned open-source package, or a GitHub feature. The bespoke code is the site itself, about 80 lines of firewall glue, and a zone audit script.

## JavaScript per page

Measured 2026-10-22 in the framework research bench, on minimal apps (Apple M4 Max, Node 24.16). A script followed every `<script src>`, modulepreload, island URL and static or dynamic import, added inline scripts, and summed the gzip -9 sizes. The full-hydration apps were minimal, so their rows are lower bounds.

| Build | JS per page, gzip | Pages that pay it |
|---|---|---|
| Astro 7.4.2, static page | 0 KiB | none |
| Astro, one vanilla web component | 0.3 KiB | pages with that effect |
| Astro, one Preact 11 island | 9.4 KiB | pages with the island |
| Astro, one React 19.3 island | 69.5 KiB | pages with the island |
| Vite 8 and React 19 SPA (the Mission-AI pattern) | 66.2 KiB, with an empty HTML body | every page |
| TanStack Start 1.169.3, prerendered | 106.7 KiB | every page |
| React Router 8.5.0 framework mode, prerendered | 111.6 KiB | every page |

What it means:

- React costs about the same wherever it loads: 69.5 KiB gzip, most of it the react-dom client (207.8 KiB before compression). A framework does not change that cost. It decides which pages pay it. Astro's default is that text pages pay nothing. TanStack Start and React Router make every page pay, including pages that are only text.
- Most of this site is text: Home, `/about/`, case studies, posts. None of them needs a runtime to show words.
- The SPA fits worst with how people arrive. Visitors come through links Joseph hands out, and the first reader of a link is often a Slack or LinkedIn unfurler. An SPA serves one `index.html` with an empty `<div id="root">` for every route, so crawlers find no text and every shared link unfurls with the same preview.
- The 5 KB gzip budget for eager JS on content pages ([design-system.md](design-system.md)) follows from this table: only the vanilla row fits under it. That is why effects are vanilla modules and React stays on lab pages.
- Bytes are a proxy. Script also has to be parsed and run on the main thread, and main-thread work is what delays Interaction to Next Paint (INP). The real check is field data: p75 LCP of 2.5 s or less and INP of 200 ms or less on text pages, the trigger in [ADR 0003](adr/0003-astro-static-first.md).
- From PR 3 the numbers become a fitness function: CI measures eager JS on every page and fails above the budget ([delivery.md](delivery.md)).

## Upgrade policy

Upgrades arrive as Dependabot PRs and pass the same pipeline as everything else: verify, firewall, preview, e2e. The rules below say when to take them; versions and dates are as of 2026-10-22. The Dependabot configuration and pnpm settings are in [delivery.md](delivery.md).

| What | Rule | Why |
|---|---|---|
| Astro and `@astrojs/*` | Exact pins. Minor and patch releases arrive in the weekly grouped PR. A major waits for its x.1 release, then lands with its integrations in one PR, prepared with `pnpm dlx @astrojs/upgrade` | Three majors between 2024-12-03 and 2026-06-22. Each x.1 followed 16 to 24 days after its .0 ([npm](https://www.npmjs.com/package/astro?activeTab=versions)); that wait lets the first round of regressions get fixed upstream. A major that takes more than a day is a trigger in [ADR 0003](adr/0003-astro-static-first.md) |
| Wrangler | `^4.152.0` from the catalog; minor releases arrive in the grouped PR | Worker Previews need 4.135.0 or later. The preview job runs each new version before the deploy job does |
| `compatibility_date` | Set at scaffold. Bump it quarterly in a PR that changes only the date for one Worker, after reading the flag changes in between. The weekly job warns at 180 days. No `compatibility_flags` for the site | Old dates keep working, so a stale date is a missing feature, not an outage ([compatibility dates](https://developers.cloudflare.com/workers/configuration/compatibility-dates/)) |
| Node | Stay on the Active LTS line in `.nvmrc`: 26 from 2026-10-28. Move when the next line reaches LTS. From Node 27 every line does, each October (27 is scheduled for 2027-10-20). Never stay on a line past its end; 25 ended 2026-06-01 ([schedule](https://github.com/nodejs/Release)) | Node runs only the build and the tests, so a move is low-risk and CI covers it |
| pnpm | Stay on 11.x through `packageManager`. Never add `devEngines.packageManager` | Pinning pnpm 12, or declaring that field, writes the two-document lockfile that turns Dependabot alerts off |
| TypeScript | Stay on 6.0.x; Dependabot ignores TypeScript majors. Move to 7 when the peer ranges of typescript-eslint and `@astrojs/check` accept it | Taking 7 now would break lint and type-check on the first CI run |
| Tailwind | Minor releases in the grouped PR. A v5 is handled like an Astro major | The output is plain CSS, so the exit cost is low |
| React | Majors touch lab pages only | Islands confine React to `/lab/<slug>/` |
| 0.x packages (PartyServer, and the Agents SDK if adopted) | Exact pins; read the changelog before every bump | Under 0.x, a minor release may break |
| gitleaks | Not managed by Dependabot. A quarterly check bumps the version and its sha256 together | The project is "feature complete" and gets security patches only ([README](https://github.com/gitleaks/gitleaks)). If patches stop, re-evaluate the engine |
| `@lhci/cli` | Watch | No release since 2025-06-26. If it falls behind Chrome, run Lighthouse from Playwright |
| Security updates | Merge once CI is green, any day of the week | Dependabot's cooldown does not apply to them |

The script between the `---` fences is the component's front matter: it runs at build time and is stripped from the page, so there is no client state unless you add an island. Files in `src/pages/` are routes | [Astro components](https://docs.astro.build/en/basics/astro-components/) |
| 2 | Islands | React 19 components, hooks, shadcn | `client:*` directives decide whether and when a component hydrates (`client:load`, `client:idle`, `client:visible`, `client:media`, `client:only`). No directive means HTML only and 0 KiB. Each island is its own React root, so context does not cross islands; share state through a small store such as Nano Stores | [Client directives](https://docs.astro.build/en/reference/directives-reference/#client-directives) |
| 3 | Content | Zod schemas | Content collections: `src/content.config.ts` declares them, the `glob()` loader reads Markdown and MDX, `z` comes from `astro/zod`, and a bad front-matter value fails the build | [Content collections](https://docs.astro.build/en/guides/content-collections/) |
| 4 | Styling | Tailwind v4, `@theme`, oklch tokens | Nothing new in the tool. The new rules: tokens live in this repo ([ADR 0010](adr/0010-quiet-console-design-tokens.md)), and shadcn appears only inside lab islands | [Theme variables](https://tailwindcss.com/docs/theme) |
| 5 | Hosting | Static files behind a CDN; bulkheads, the way a Go service gives each slow dependency its own bounded pool | Wrangler's `assets` block: `directory`, `not_found_handling: "404-page"`, `html_handling: "auto-trailing-slash"`. No `main` means an assets-only Worker: no code runs and nothing is billed. `_headers` and `_redirects` apply to asset responses only | [Wrangler configuration: assets](https://developers.cloudflare.com/workers/wrangler/configuration/#assets) |
| 6 | Versions | Blue/green deploys, rollbacks | A version is an immutable snapshot of code, assets and config; a deployment says which version takes traffic. CI uploads a version, smoke-tests its Version URL, then deploys it at 100%. Rollback reaches the 100 most recent versions | [Versions and deployments](https://developers.cloudflare.com/workers/configuration/versions-and-deployments/) |
| 7 | Previews | Preview environments per pull request | `wrangler preview --name pr-<n>` creates an isolated environment per branch under the same Worker, on workers.dev with `X-Robots-Tag: noindex`. DO namespaces are isolated per preview; KV, D1 and R2 are shared unless bound separately | [Worker Previews](https://developers.cloudflare.com/workers/previews/) |
| 8 | Runtime version | Pinning dependencies | `compatibility_date` pins the Workers runtime's behavior for one Worker, independent of the Wrangler version | [Compatibility dates](https://developers.cloudflare.com/workers/configuration/compatibility-dates/) |
| 9 | Tooling | pnpm workspaces, TypeScript | pnpm 11 defaults. pnpm prefers versions at least a day old (`minimumReleaseAge` 1440 minutes); [delivery.md](delivery.md) explains the loose default and when a fresh Dependabot lockfile fails CI. Installs fail on unreviewed build scripts (`allowBuilds` lists esbuild and workerd). The `"pnpm"` field in `package.json` is ignored | [pnpm 11.0 release notes](https://pnpm.io/blog/releases/11.0) |
| 10 | Lab: Durable Objects (*later*) | Single ownership: one goroutine owns a piece of state and others send it messages | The actor model. Each DO has a globally unique name and its own SQLite storage. Its code runs on one thread, and storage calls hold other events back, so storage logic needs no locks. An `await fetch()` does let other requests run in between, so a read-modify-write across one needs a version check ("Rules of Durable Objects", below). A DO stays in the data center where it was created | [What are Durable Objects?](https://developers.cloudflare.com/durable-objects/concepts/what-are-durable-objects/) |
| 11 | Lab: hibernation (*later*) | WebSockets | The WebSocket Hibernation API. `ctx.acceptWebSocket()` lets an idle object leave memory while clients stay connected; `setWebSocketAutoResponse` answers pings without waking it. No `setInterval`: timers prevent hibernation. Memory is lost on hibernation, so per-connection state goes in attachments (up to 16,384 bytes) | [WebSockets in Durable Objects](https://developers.cloudflare.com/durable-objects/best-practices/websockets/) |
| 12 | Lab: tests (*later*) | Vitest | `@cloudflare/vitest-plugin` runs tests inside the Workers runtime, so DO storage and alarms behave as they do in production | [Vitest integration](https://developers.cloudflare.com/workers/testing/vitest-integration/) |

## Patterns and further reading

- Islands architecture (partial hydration): HTML everywhere, JS only where it earns its bytes. Jason Miller, ["Islands Architecture"](https://jasonformat.com/islands-architecture/) (2020). The JavaScript table above is the cost argument.
- Rendering costs: Jason Miller and Addy Osmani, ["Rendering on the Web"](https://web.dev/articles/rendering-on-the-web) (web.dev).
- Progressive enhancement: native view transitions and vanilla effects. Every page works without them. Jeremy Keith, [*Resilient Web Design*](https://resilientwebdesign.com/) (2016).
- Fitness functions: the JS, CSS and font budgets as CI checks. Neal Ford, Rebecca Parsons, Patrick Kua and Pramod Sadalage, *Building Evolutionary Architectures*, 2nd ed., ch. 2, "Fitness Functions".
- Bulkhead: the assets-only site Worker apart from the lab Worker. Michael Nygard, *Release It!*, 2nd ed., ch. 5, "Stability Patterns".
- Schema-on-write: Zod-validated collections fail the build instead of the page. Martin Kleppmann, *Designing Data-Intensive Applications*, the section on schema-on-read versus schema-on-write.
- Single writer: one pipeline deploys production. Martin Thompson, ["Single Writer Principle"](https://mechanical-sympathy.blogspot.com/2011/09/single-writer-principle.html) (2011).
- Choose boring technology: this stack spends its novelty on Durable Objects and keeps every other layer conventional. Dan McKinley, ["Choose Boring Technology"](https://mcfunley.com/choose-boring-technology) (2015).
- Before the first demo: Cloudflare, ["Rules of Durable Objects"](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/).
- Canonical sources for every pattern named in these docs: [reading-list.md](reading-list.md).
